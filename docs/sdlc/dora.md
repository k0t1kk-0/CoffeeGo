# DORA-рефлексія

**Deployment Frequency.** Тижневі спринти з показом на staging щоп'ятниці дають щонайменше один реліз на тиждень. Після запуску команда переходить на Kanban: кожна задача після злиття автоматично розгортається CI/CD, тож серверні зміни можна випускати кілька разів на день.

**Lead Time for Changes.** Задачі на дошці дрібні (4–14 год), тому кожна проходить шлях від To Do до Done за 1–2 дні. Колонка Review з лімітом незавершеної роботи не дає задачам накопичуватися, а CI запускає тести одразу після Pull Request.

**Change Failure Rate.** Ризик збою знижують обов'язковий Code Review, автотести в CI і перевірка за критерієм прийнятності перед переміщенням у Done. Нова версія застосунку спершу йде в пілотну кав'ярню.

**MTTR.** Кожен реліз — окремий тег у Git, тож відкат серверної частини займає хвилини. Інциденти заводяться на дошку з міткою Bug і пріоритетом Critical, SLA — реакція протягом 1 год. Замовлення при збої POS зберігаються в черзі й передаються повторно.
